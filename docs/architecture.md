# Архитектура

## Обзор

Сервис — HTTP API для обмена информацией об угрозах. Реализация на Go 1.24, HTTP — стандартный `net/http`, конфигурация — YAML + переменные окружения через `cleanenv`. Хранилище in-memory.

## Слои

| Пакет | Ответственность |
|---|---|
| `cmd/server` | точка входа: конфиг, логгер, `http.Server`, graceful shutdown |
| `internal/config` | загрузка настроек из YAML и env |
| `internal/threat` | домен: модель, нормализация, валидация |
| `internal/storage` | интерфейс `Store` и in-memory реализация |
| `internal/api` | HTTP: маршруты, DTO, маппинг ошибок |

Зависимости направлены внутрь: `api` знает про `threat` и `storage`, `storage` — про `threat`. Домен не импортирует HTTP и хранилище.

## Поток запроса

**`POST /info`**

1. Проверка `Content-Type` → `415`.
2. Ограничение размера тела → `413`.
3. Декодирование JSON и проверка отсутствия данных после объекта → `400`. Неизвестные поля игнорируются.
4. DTO → `threat.Threat`, затем `threat.New`: нормализация и валидация → `400` с перечнем полей.
5. `storage.Create`; занятый MD5 → `409`.
6. `201` и DTO в camelCase.

**`GET /info/{md5}`**

1. `threat.ParseMD5` нормализует MD5 из пути (upper → lower) и валидирует → `400`.
2. `storage.Get`; запись не найдена → `404`.
3. `200` и DTO.

**`PUT /info/{md5}`**

1. MD5 из пути валидируется первым и имеет приоритет над телом.
2. Декодирование и валидация — как в `POST`.
3. `storage.Replace`; запись не найдена → `404`.
4. `200` и DTO.

## Валидация и нормализация

- **MD5** — 32 шестнадцатеричных символа, приводится к нижнему регистру.
- **name** — обрезаются краевые пробелы, длина 1–255 рун.
- **description** — обрезаются краевые пробелы, не более 2000 рун; пустое значение допустимо.
- **category / severity** — отсутствие или `null` даёт `unknown`; явная пустая строка `""` отклоняется с `400`; остальные значения проверяются по enum.
- **tags** — обрезаются пробелы, приводится нижний регистр, выполняется сортировка и дедупликация; не более 30 уникальных тегов, каждый 1–50 рун; отсутствие или `null` даёт `[]`.
- **firstSeen / lastSeen** — необязательные, приводятся к UTC; `lastSeen` не может быть раньше `firstSeen`, равные даты разрешены.

Явная проверка пустых `category`/`severity` живёт в `api.buildThreat`, потому что домен трактует `""` как «не передано» и подставляет `unknown`.

## Ошибки

| Код | Причина |
|---|---|
| `400` | невалидный JSON, MD5, поля или trailing data |
| `404` | запись не найдена |
| `409` | MD5 уже существует |
| `413` | тело больше `BODY_LIMIT` |
| `415` | `Content-Type` не `application/json` |
| `500` | неожиданная ошибка; детали пишутся в лог, наружу не отдаются |

Тело ошибки — `{"message": "...", "details": "..."}`; оба поля присутствуют всегда.

## Хранилище

`storage.Memory` — `map[string]threat.Threat` под `sync.RWMutex`.

- `Create`/`Replace` берут `Lock`, `Get` — `RLock`.
- `ErrNotFound` и `ErrAlreadyExists` оборачиваются через `%w`, handler проверяет их через `errors.Is`.
- `cloneThreat` копирует теги и даты на входе и выходе, поэтому мутация полученной структуры не меняет данные в хранилище.

## Конфигурация и Docker

Переменные окружения перекрывают значения из `cmd/server/config.yaml` (теги `env` в `internal/config`). В Docker адрес задаётся как `API_ADDRESS=0.0.0.0:8080`, иначе сервис слушает loopback контейнера и недоступен с хоста.

Образ собирается в две стадии: `golang:1.24-alpine` компилирует статический бинарник, `alpine:3.20` содержит только его и конфиг. Контейнер работает от пользователя `app` (uid 10001), healthcheck обращается к `GET /health`.
